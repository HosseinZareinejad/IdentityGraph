# IdentityGraph

سیستمی که مجموعه‌ای از حساب‌های پراکنده در چند شبکه اجتماعی را به یک «هویت مجازی» واحد گره می‌زند، و بعد آن هویت مجازی را به یک شخص حقیقی در یک پایگاه ثبت رسمی نگاشت می‌کند — با شواهدی که قابل خواندن باشند و اطمینانی که معنای واقعی داشته باشد.

نتایج کامل و روش سنجش: **[docs/RESULTS.md](docs/RESULTS.md)** — اعداد ماشین‌خوان در `data/metrics.json`.

| پرسش | پاسخ |
|---|---|
| با داشتن یک خوشه حساب، شخص حقیقی درست را نام می‌بریم؟ | **۸۲.۲٪** top-1 (۹۲.۵٪ top-5) |
| وقتی سیستم حاضر به پاسخ‌دادن می‌شود | **۹۱.۴٪** دقت، روی ۸۵.۲٪ خوشه‌ها |
| روی افرادی که «همزاد» دارند (نام+شهر+سال تولد یکسان) | **۶۶.۰٪** top-1 |
| حساب‌های گره‌خورده واقعاً به هم تعلق دارند؟ | **B-cubed F1 ۰.۸۸۹** (P ۰.۹۱، R ۰.۸۷) |
| سقف سیستم: کاندیداسازی اصلاً جفت درست را می‌بیند؟ | **۹۷.۰٪** recall |

روی ۱۷۵۲ خوشه از افرادی که هیچ مدلی در آموزش یا کالیبراسیون ندیده است. خط لوله قطعی است: دو اجرای پیاپی `scripts/evaluate.py` خروجی یکسان می‌دهند.

### چرا این تصمیم‌ها

**Fellegi-Sunter به‌جای فرمول وزن‌دار دستی.** فرمول قبلی (`0.4×بردار + 0.4×نام + 0.2×یوزرنیم`) فیلد غایب را با شباهت ۰.۰ حساب می‌کرد، یعنی نبودِ داده را **مدرکی علیه** تطابق می‌گرفت. با توجه به جدول پوشش (شغل فقط در لینکدین، تلفن تقریباً فقط در تلگرام)، این باگ دقیقاً همان جفت‌های کم‌داده‌ای را جریمه می‌کرد که سیستم برای پیدا کردنشان ساخته شده. در Fellegi-Sunter سطح «غایب» وزن دقیقاً صفر دارد، وزن‌ها از داده یاد گرفته می‌شوند (`log₂ m/u`)، و هر تصمیم به سهم هر ویژگی بر حسب بیت تجزیه می‌شود.

**تطبیق مقید به‌جای connected components.** بستار تراگذری یک شکست شناخته‌شده دارد: یک یال غلط دو هویت درست را به هم جوش می‌دهد و خرابی زنجیره‌ای می‌شود. در همین داده، خوشهٔ بزرگ به **۴۵۵** حساب می‌رسید. چون هر فرد حداکثر یک حساب در هر پلتفرم دارد، پاسخ درست بین هر دو پلتفرم یک تطبیق ۱-به-۱ است؛ با حل مجارستانی روی هر مؤلفه و سپس حذف خوشه‌های خودمتناقض، بزرگ‌ترین خوشه به ۴ و B-cubed F1 از ۰.۶۷۵ به ۰.۸۸۹ می‌رسد.

**B-cubed به‌جای F1 جفتی.** F1 جفتی ادغام بیش‌ازحد را می‌پوشاند: یک خوشهٔ غول‌آسا هنوز جفت‌های زیادی را درست می‌زند. B-cubed هر حساب را جدا جریمه می‌کند.

**اطمینان دو مرحله‌ای.** احتمالِ هر کاندیدا به «آیا *این* یکی درست است؟» جواب می‌دهد؛ داشبورد «آیا *بهترین حدسم* درست است؟» را نشان می‌دهد — سؤالی آسان‌تر، چون argmax است. علاوه بر آن، اطمینان باید **ابهام** را ببیند: دو همزاد شواهدی کاملاً یکسان و کاملاً قانع‌کننده تولید می‌کنند. اطمینان نمایش‌داده‌شده تابعی است از امتیاز کاندیدای اول **و** سهم او از کل جرم کاندیداها (≈۰.۵ در تساوی دوطرفه)، که با رگرسیون لجستیک ترکیب و با isotonic روی نیمه‌های مجزای دادهٔ کنارگذاشته کالیبره می‌شود.

## اعتبارسنجی روی دادهٔ واقعی

دادهٔ مصنوعی را همان کسی نوشته که تطبیق‌دهنده را نوشته، پس به‌تنهایی فقط ثابت می‌کند سیستم بر تصورِ نویسنده از نویز غلبه می‌کند. اجزای مربوط به نام روی **۷۸۱۲ جفت نام واقعی (فارسی، انگلیسی) از ویکی‌داده** سنجیده شده‌اند — رومن‌نویسی‌هایی که ده‌ها ویراستار انسانی بی‌ارتباط با این پروژه نوشته‌اند.

```bash
python scripts/validate_real_data.py
```

این کار چند نقص واقعی را لو داد و همه اصلاح شدند (جزئیات در [docs/RESULTS.md](docs/RESULTS.md) §۷): کلید فونتیک ض/ظ/ح را جا انداخته بود؛ یوزرنیم‌های مصنوعی بدون واکه بودند و کار را از واقعیت آسان‌تر می‌کردند؛ و مقایسه در فضایی انجام می‌شد که دو رومن‌نویسی از یک نام هرگز در آن به توافق نمی‌رسند. پس از اصلاح، بازیابی بین‌خطی روی داده واقعی از ۶۶.۱٪ به **۹۰.۰٪** top-1 رسید؛ همین اصلاح جستجوی اپراتور را هم درست کرد: تایپ «mohammadreza» دیگر حساب‌هایی را که «mhmdrza» نوشته شده‌اند برمی‌گرداند.

برای مراحل گره‌زنی و نگاشت، پیکرهٔ عمومی برچسب‌خوردهٔ چندپلتفرمی فارسی وجود ندارد؛ آن مراحل فقط روی دادهٔ مصنوعی سنجیده شده‌اند و این محدودیت پنهان نشده است.

## آنچه ابلیشن دربارهٔ پروپوزال می‌گوید

پروپوزال پنج مدل هوش مصنوعی تعریف کرده بود. اندازه‌گیری روی split اعتبارسنجی:

| مجموعه ویژگی | F1 | recall روی جفت‌های دارای تماس قطعی |
|---|---|---|
| فقط نام | ۰.۹۲۱۲ | ۹۱.۴٪ |
| هر شش مدالیته | ۰.۹۲۷۴ | **۱۰۰٪** |

**ویژگی‌های نام به‌تنهایی به ۹۹.۳٪ مدل کامل می‌رسند.** امبدینگ متن، سبک‌شناسی، ریتم زمانی و ساختار گراف روی هم +۰.۰۰۶ F1 می‌ارزند. تنها جایی که اختیاری نیستند متادیتا است: تلفن و ایمیل قطعی نادرند اما وقتی هستند پرونده را می‌بندند.

هر ۳۲ زیرمجموعهٔ ممکن سنجیده شد؛ کل فضا بین ۰.۹۲۱۲ و ۰.۹۲۷۷ است در برابر خطای معیار ۰.۰۰۵۷ — یعنی تفاوت‌ها نویزند و انتخاب بر مبنایشان overfit کردنِ همان split است. هیچ مدالیته‌ای حذف نشد.

## اجرا

نیازمندی‌ها: Docker، Python 3.11+، Node.js 18+.

```bash
docker compose up -d qdrant
python -m venv venv && .\venv\Scripts\activate && pip install -r requirements.txt
```

**ساخت دنیا و آموزش:**

```bash
python data/generate_synthetic_world.py && python etl/run_all.py && python etl/validate.py && python scripts/train_fusion.py && python scripts/train_mapper.py
```

**سنجش:**

```bash
python scripts/evaluate.py && python scripts/validate_real_data.py
```

**سرویس:**

```bash
uvicorn api.main:app --host 127.0.0.1 --port 8500
```

```bash
cd ui && npm install && npm run dev
```

> پورت ۸۵۰۰ عمدی است. در ویندوز با Hyper-V فعال، بازهٔ ۷۹۳۶–۸۴۳۵ رزرو شده و بایند روی ۸۰۰۰ با خطای «socket forbidden» رد می‌شود. با `netsh interface ipv4 show excludedportrange protocol=tcp` قابل بررسی است.

## نقشهٔ فایل‌ها

| مسیر | نقش |
|---|---|
| `data/generate_synthetic_world.py` | تولید دنیای مصنوعی: ثبت احوال، ۴ دامپ پلتفرم، گراف‌ها، همزادها |
| `etl/` | پاک‌سازی، ویژگی‌های گراف، بارگذاری Qdrant، اعتبارسنجی ETL |
| `src/text_utils.py` | نرمال‌سازی، کلید فونتیک، ترانویسی، رومن‌نویسی واکه‌دار، اسکلت هم‌خوان |
| `src/blocking.py` | کاندیداسازی چندمسیره |
| `src/models/` | ویژگی‌های هر مدالیته + `fusion_model.py` (Fellegi-Sunter) |
| `src/clustering.py` | تطبیق ۱-به-۱ مقید + بهداشت خوشه |
| `src/real_identity_mapper.py` | نگاشت خوشه → شخص حقیقی، کالیبراسیون آگاه به ابهام |
| `scripts/evaluate.py` | گزارش یکپارچه → `data/metrics.json` |
| `scripts/validate_real_data.py` | اعتبارسنجی اجزا روی نام‌های واقعی ویکی‌داده |
| `api/main.py`, `ui/` | API پرونده و داشبورد |

کد قدیمیِ تک‌پلتفرمی (`ingestion.py`, `resolution.py`, `src/scorer.py`, `src/retriever.py`) برای مسیر `/resolve` قدیمی حفظ شده و در خط لولهٔ اصلی استفاده نمی‌شود.

## محدودیت‌ها

- گره‌زنی و نگاشت فقط روی دادهٔ مصنوعی سنجیده شده‌اند. اعداد §۶ سقفِ کار روی داده واقعی نیستند، ولی ساختار خطا (چه چیزی کجا می‌شکند) قابل انتقال است.
- خوشه‌ای که به لینکدین یا تلگرام نرسیده باشد، برای همزادها **تصمیم‌ناپذیر** است — نه سخت، بلکه فاقد اطلاعات لازم. سیستم در این موارد امتناع می‌کند و در UI برچسب «مورد مناقشه» می‌زند.
- بازخورد اپراتور (تأیید/رد) ذخیره می‌شود اما هیچ مدلی خودکار بازآموزی نمی‌شود.
- تصویر پروفایل عمداً پوشش داده نشده است.
- ۱۴.۱٪ خوشه‌ها «مورد مناقشه»اند و دقت top-1 در آن‌ها ۴۴.۹٪ است در برابر ۸۸.۴٪ بقیه. این‌ها همان‌هایی‌اند که باید به اپراتور انسانی برسند.
